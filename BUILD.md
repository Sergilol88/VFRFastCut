# Building VFR FastCut on Windows

## 1. Install pinned Python dependencies

Release builds should use the exact dependency versions committed in `requirements.txt`.

```powershell
python -m pip install -r requirements.txt
python -m pip install pyinstaller
```

For VFR FastCut v0.2.36 Windows x64:

```text
PySide6 6.11.2
Qt 6.11.2
```

Verify before building:

```powershell
python -c "import PySide6; print(PySide6.__version__)"
python -c "from PySide6.QtCore import qVersion; print(qVersion())"
```

## 2. Build and verify the minimal FFmpeg runtime

The v0.2.36 portable package uses the project-specific runtime under:

```text
tools\ffmpeg-minimal\
```

From the MSYS2 UCRT64 shell:

```bash
cd /c/Users/user/VFRFastCut
./tools/ffmpeg-minimal/build-msys2-ucrt64.sh
```

The release runtime is generated in:

```text
tools\ffmpeg-minimal\runtime\
```

The exact corresponding FFmpeg source archive is generated as:

```text
tools\ffmpeg-minimal\ffmpeg-9.0.2-source.tar.xz
```

From PowerShell, verify the runtime against a representative real VFR/Twitch sample:

```powershell
.\tools\ffmpeg-minimal\verify.ps1 -InputFile "D:\video\sample-vod.mp4"
```

A release build should not proceed until all smoke tests pass.

## 3. Confirm third-party license files

The following files must exist before the PyInstaller build:

```text
LICENSES\LGPL-2.1.txt
LICENSES\MinGW-w64-libwinpthread-COPYING.txt
LICENSES\GCC-COPYING.LIB.txt
LICENSES\GCC-COPYING.RUNTIME.txt
LICENSES\GCC-COPYING3.txt
LICENSES\GCC-runtime-README.txt
```

Exact component/package versions are recorded in `THIRD_PARTY_VERSIONS.md`.

## 4. Build the portable application

From the repository root in PowerShell:

```powershell
Remove-Item .\build -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item .\dist -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item .\VFRFastCut.spec -Force -ErrorAction SilentlyContinue
```

Build the application itself without the old Gyan FFmpeg binaries:

```powershell
python -m PyInstaller --noconfirm --clean --onedir --windowed --contents-directory "." --name "VFRFastCut" --icon "VFRFastCut.ico" --add-data "VFRFastCut.ico;." --add-data "LICENSE;." --add-data "THIRD_PARTY_NOTICES.md;." --add-data "THIRD_PARTY_VERSIONS.md;." --add-data "README.md;." --add-data "README_RU.md;." --add-data "LICENSES;LICENSES" vfr_fastcut.py
```

Create the FFmpeg payload directory and copy the entire verified custom runtime:

```powershell
New-Item -ItemType Directory -Force .\dist\VFRFastCut\ffmpeg\bin | Out-Null
Copy-Item .\tools\ffmpeg-minimal\runtime\* .\dist\VFRFastCut\ffmpeg\bin\ -Force
```

Do not copy FFmpeg/FFprobe from `C:\ffmpeg` for v0.2.36.

Result:

```text
dist\VFRFastCut\
```

The whole folder is the portable application.

## 5. Portable smoke test

Temporarily make any system FFmpeg unavailable so the test proves that the packaged runtime is self-contained:

```powershell
Rename-Item C:\ffmpeg C:\ffmpeg_BACKUP
```

Start:

```powershell
.\dist\VFRFastCut\VFRFastCut.exe
```

Test at minimum:

1. Open a representative VFR/Twitch MP4.
2. Video + audio lossless export to MP4.
3. Video-only export.
4. Audio-only export to MKA.
5. Selected-segment export.
6. Multi-range export with a middle segment removed.
7. Cancel Export.
8. RU ↔ EN language switching and persistence.
9. F1 help.
10. Confirm the portable folder contains `ffmpeg\bin\BUILD_INFO.txt`, FFmpeg DLLs, both MinGW runtime DLLs and the license files.

Restore the system FFmpeg after testing:

```powershell
Rename-Item C:\ffmpeg_BACKUP C:\ffmpeg
```

## 6. Create the Release archive

```powershell
Remove-Item .\VFRFastCut-v0.2.36-Windows-x64.zip -Force -ErrorAction SilentlyContinue
tar.exe -a -c -f VFRFastCut-v0.2.36-Windows-x64.zip -C dist VFRFastCut
```

Create the checksum:

```powershell
(Get-FileHash .\VFRFastCut-v0.2.36-Windows-x64.zip -Algorithm SHA256).Hash.ToLower() |
    Set-Content .\VFRFastCut-v0.2.36-Windows-x64.zip.sha256 -Encoding ascii
```

## 7. Release assets

Publish these assets with the GitHub Release:

```text
VFRFastCut-v0.2.36-Windows-x64.zip
VFRFastCut-v0.2.36-Windows-x64.zip.sha256
ffmpeg-9.0.2-source.tar.xz
```

The FFmpeg source archive should be the exact file generated by the release runtime build.

## Notes

- `--onedir` is intentional: it starts faster, is easier to diagnose, and keeps third-party runtime files visible.
- Generated `build/`, `dist/`, FFmpeg build trees/runtime, source tarballs and local Release ZIPs are ignored by Git.
- VFR FastCut source code remains MIT-licensed; redistributed third-party components remain subject to their own licenses.
